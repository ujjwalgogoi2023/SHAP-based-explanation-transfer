# Two Benchmarks, One Feature Space

An exploratory data analysis of distribution shift between **CICIDS2017** and
**UNSW-NB15**, the two most widely used network intrusion detection benchmarks.

This is a fork of the deep-learning project in `../DL`, re-cut as an EDA study.
The research question is the same — can a detector, and the SHAP explanation
attached to it, be carried from one benchmark to another — but here it is
answered from the data alone, before any model is fitted. The parent project's
modelling results are read in only at the final stage, as held-out evidence that
the EDA diagnostics anticipated the outcome.

**Deliverable:** `report/EDA_Report_CICIDS2017_UNSW-NB15.docx` and `.pdf` --- a
17-page paper in two-column IEEE format, black and white throughout, with 16
figures, 10 tables in the body and 52 references.

## What the analysis found

| | |
|---|---|
| Records examined | 3,088,416 raw flows across 10 source files (932 MB) |
| Quality defects (CICIDS2017) | 8 constant columns, 13 with negative values in non-negative quantities, 2 with infinities, 1 duplicated column name, 65 names with leading whitespace, labels not valid UTF-8 |
| Exact duplicate records | 10.9% of CICIDS2017, 36.8% of UNSW-NB15 |
| Class imbalance | 206,645:1 (CICIDS2017 raw labels), 534:1 (UNSW-NB15) |
| Skewness | median \|skew\| 25.4 → 0.80 under log1p; features span 9 orders of magnitude |
| Multicollinearity | max VIF 6,249; 5 principal components carry 90% of 12 features' variance |
| Distribution shift | **all 12 shared features exceed the PSI 0.25 "major shift" threshold**; mean KS D = 0.38 |
| Within-class shift | mean \|SMD\| = 1.52 against Cohen's 0.8 for a large effect |
| Corpus separability | **domain-classifier AUC = 0.99998** from the 12 shared features alone |
| Model-free ranking disagreement | mutual-information feature rankings agree at Spearman ρ = +0.17 on average; zero top-3 overlap for Benign and DoS/DDoS |

Held against the parent project: macro F1 falls from 0.923 within CICIDS2017 to
0.118 under transfer (MCC −0.032, marginally worse than chance), while the same
architecture trained natively on UNSW-NB15 reaches 0.722. Ranking the four
classes by the shift measured here against their transfer F1 gives ρ = −0.80.

## Layout

```
src/eda/settings.py          paths, palette, shared matplotlib style
src/eda/ingest.py            stage 1 — raw CSV reading, per-column quality audit, cache
src/eda/common.py            loading helpers, descriptives, divergence measures, MI
src/eda/stage_quality.py     stage 2 — defects, attrition, duplication, class balance
src/eda/stage_univariate.py  stage 3 — shape, transform justification, outliers, ECDFs
src/eda/stage_multivariate.py stage 4 — correlation, VIF, clustering, feature↔class MI
src/eda/stage_shift.py       stage 5 — KS/PSI/JSD, class-conditional SMD, domain classifier, PCA
src/eda/stage_synthesis.py   stage 6 — join to the parent project's modelling results
src/eda/report.py            builds the paper from the figures, tables and bibliography
scripts/run_eda.py           runs all six stages
scripts/build_report.py      builds the .docx and converts it to .pdf

eda_results/figures/         16 figures, each as 300-dpi PNG and PDF
eda_results/tables/          27 result tables as CSV
eda_results/cache/           harmonised feature matrices (regenerated by stage 1)
report/                      the deliverable

src/data/schema.py           feature and label harmonisation, carried over from ../DL
results/                     the parent project's modelling output, read only by stage 6
```

`src/models`, `src/training`, `src/eval`, `src/explain`, `notebooks/`, `paper/`
and the original `scripts/` are carried over from the parent project and are not
used by the EDA. They are kept so stage 6's inputs can be traced back to the code
that produced them.

## Running it

```bash
pip install -r requirements.txt
python scripts/run_eda.py          # all six stages
python scripts/build_report.py     # .docx + .pdf
```

Stage 1 reads ~0.9 GB of raw CSVs and takes a few minutes. Every later stage
reads the cached harmonised matrix, so iterating on figures is fast:

```bash
python scripts/run_eda.py --from 2   # reuse the cache
python scripts/run_eda.py --only 5   # one stage
```

Point `CICIDS_DIR` and `UNSW_DIR` in `src/eda/settings.py` at the raw download
directories. Both datasets are free and need no licence agreement:

| Dataset | Files used | Source |
|---|---|---|
| CICIDS2017 | all 8 `*.pcap_ISCX.csv` | https://www.unb.ca/cic/datasets/ids-2017.html |
| UNSW-NB15 | `UNSW_NB15_training-set.csv` + `testing-set.csv` only | https://research.unsw.edu.au/projects/unsw-nb15-dataset |

**The UNSW glob is deliberately narrow.** That distribution also ships
`UNSW-NB15_1..4.csv` (49 columns, *no header row*) plus metadata files. A bare
`*.csv` glob concatenates all of them into a mostly-NaN frame without raising,
so the loader matches `UNSW_NB15_*-set.csv` and rejects mismatched column counts.

**Anaconda on Windows:** pip-installed torch and Anaconda's MKL both ship
`libiomp5md.dll`, which aborts at import with `OMP: Error #15`. The EDA itself
does not need torch, but if the environment has it, set:

```bash
set KMP_DUPLICATE_LIB_OK=TRUE
```

The PDF is produced by driving the installed Microsoft Word through COM, which
is the only converter on this machine that renders the tables and embedded
figures faithfully. Without Word the `.docx` is still written and the conversion
is reported as skipped rather than failing the build.

## Analysis decisions that affect the result

**The quality audit runs before harmonisation.** Once the twelve-feature matrix
exists, a missing value has become a dropped row, a constant column has been
excluded and a mojibake label has been canonicalised. Several findings in
Section 3 of the report are only visible on the raw columns, so stage 1
accumulates per-column statistics file by file and caches afterwards.

**Scale-sensitive analyses use log1p; descriptives do not.** All twelve features
are non-negative, zero-inflated and span up to nine orders of magnitude, so a
mean, a standard deviation and a three-sigma band are all misleading on the
native scale. log1p is chosen over Box-Cox or quantile normalisation because it
*estimates nothing*: a fitted transform in a cross-dataset study raises the
question of which dataset it was fitted on. Descriptive statistics are still
reported in the original units.

**No outlier filter is applied.** Tukey's rule flags 16.0% of CICIDS2017 records
on average and the three-sigma rule 1.0% — a disagreement that is itself the
diagnosis. Dropping 16% would discard most of the attack traffic, since high
packet rates and large byte volumes are what a volumetric denial-of-service flow
*is*. Extreme values here are the phenomenon, not contamination.

**Duplicate detection excludes identifier columns.** UNSW-NB15 carries a
surrogate row `id`, which makes every record unique by construction and would
report zero duplicates whatever the traffic looked like.

**Divergence is reported as effect size, never as a p-value.** At 2.8 million
records against 171,705 every two-sample test rejects at any level for any
difference at all, so only KS D, PSI, Jensen-Shannon divergence and standardised
mean differences carry information.

**Both datasets are binned identically.** Divergence bin edges are built from the
pooled sample, so the figure measures the distributions rather than the binning.
PSI is the exception: its bins come from the reference sample, which is the
convention its thresholds were calibrated under.

**PCA is fitted on CICIDS2017 alone.** UNSW-NB15 is projected into that basis
rather than into a pooled one, mirroring how a source-fitted scaler is applied to
a target in the transfer setting. The picture then shows the target through the
source's coordinate system, which is what a transferred model actually sees.

**Scatter samples are class-balanced, not proportional.** A proportional draw from
a corpus that is 80% benign is a picture of benign traffic. Every subsample is
balanced across the four classes and its size is stated in the figure caption.

**Mutual information is binned, not kNN-estimated.** sklearn's kNN estimator is
two orders of magnitude slower than everything else in the pipeline at 2.8
million rows, and for ranking twelve features against each other a quantile-binned
estimate with a fixed bin count is both adequate and reproducible.

**The report is generated, not written.** Every figure is placed and every
number is interpolated from `eda_results/tables/` at build time, so the prose
cannot quote a stale value after a re-run. Section and table numbers, figure
references and citation numbers are assigned by `report.py` as the document is
laid out --- references in order of first citation, as IEEE style requires ---
so the body text holds `Section 4.2` and `[@massey1951]` and the document shows
`Section IV-B` and `[37]`.

**Section 7's class-level agreements are descriptive.** Four classes cannot
support a significance test and none is claimed; the direction and magnitude are
what the EDA is being judged on.

## Relationship to the parent project

`../DL` trains a hybrid CNN-LSTM on CICIDS2017 across five seeds, applies it
unchanged to UNSW-NB15, and compares per-class SHAP rankings against a
random-permutation floor and a same-dataset reseed ceiling. Nothing in this
project retrains or re-explains anything. Stage 6 reads `results/tables/` and
joins it to what stages 2-5 measured; the two projects are otherwise
independent, and the original README is kept as `README_DL_original.md`.
